- M4: the renderer legacy `setMode` fallback was deleted. The source-string absence pin was removed and replaced by a semantic App test that supplies only `setMode` and proves it is never invoked, with canonical `setRoute` positive controls.
- R1: registration retains the returned controls and the exact dev-only harness registers human-reachable open/capture/reset+advance/next+reset/close shortcuts. Evidence capture uses the selected matrix case/repetition; every advance resets to a blank conversation. The spike suspends the routed product native view while open, explicitly detaches on close, and restores only the same route/view. No ChatGPT upload mechanism, selector, OAuth origin, or capability result was invented.
- Disabled persisted ChatGPT route: boot requests use an explicit envelope; disabled boot targets normalize to Flow before view creation, while explicit disabled target switches reject without side effects.
- Transient ChatGPT load failure: failed views are removed from the started set. Later target entry and explicit reconnect can retry the preserved secure view; reconnect also focuses it.
- Reconnect UI: both the ChatGPT login action and authenticated badge reattach the current route and call `reconnectSession('chatgpt')`; neither uses the Flow token path or resets layout.
- Stored-route boot failure: boot-only failure reconciliation adopts the route returned by main. Interactive route failures still preserve the prior renderer route and storage.
- Probe overlap: only the latest invocation may publish readiness; deferred inversions cover stale-ready/new-blocked and stale-blocked/new-ready.
- Retry quiescence: `retryScene` and `retryErrors` both use `startTracked`; independent tests prove neither can outlive the renderer quiesce receipt.
- Provider price minor: empty Flow price spans are omitted and non-empty prices have CSS.

## Deliberate dispositions

- Stale quiesce owner without cleanup: no behavioral relaxation was made. Explicit owner unregister already rejects pending requests immediately. If a renderer disappears without a trustworthy unregister/receipt channel, the bounded 30-second wait remains an intentional fail-closed backstop; no route/view commit occurs. This is now documented beside the timeout.
- `isPackaged:true` plus `VITE_DEV_SERVER_URL`: kept deliberately as the §10 development-runtime signal because predev can rename the binary and make `app.isPackaged` report true. Selectability still requires darwin plus exact flag value `AUTOFLOWCUT_CHATGPT_P2 === '1'`; ordinary packaged launches have no VITE URL and remain closed. Existing negative cases and the non-default packaged+VITE positive control stay pinned.
- R1 full-window behavior was not migrated into the product route. It remains dynamically imported only behind the exact spike gate, suspends the one product native view while open, and has an explicit close/restore path.
