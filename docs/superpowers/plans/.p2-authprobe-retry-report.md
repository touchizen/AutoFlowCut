## Exact first-open behavior

If `did-finish-load` beats React hydration, a logged-in user can briefly retain the UI's initial `○ 로그인 필요` display while the probe is pending. The first `{ composer:false, loginCta:false }` result no longer publishes `login-required`: the target re-evaluates at 500 ms intervals, up to five total attempts. As soon as `#prompt-textarea` appears, the chip automatically changes to `● 로그인됨` and image admission becomes ready without reconnect or job admission. With fast evaluations, the hydration window is at most about 2 seconds after the first evaluation.

If all five results remain `{false,false}`, the target returns `session-blocked`; it never asserts that this unmeasured DOM means the user must log in. The current UI renders any non-ready state with the generic `○ 로그인 필요` label, but the main-process status remains correctly fail-closed as `session-blocked`.

## Bounded latency and preserved boundaries

- Load wait: at most 15,000 ms.
- Evaluation: at most 10,000 ms per attempt.
- Hydration retry: five attempts with four 500 ms intervals.
- New theoretical worst-case probe latency: `15,000 + (5 × 10,000) + (4 × 500) = 67,000 ms`.
- A measured composer returns `ready` immediately; a measured login CTA returns `login-required` immediately, including when the composer is also present.
- Missing view/webContents, `whenLoaded` false, evaluation throw/rejection/timeout, malformed result, ambiguous exhaustion, and unrecognised status remain `session-blocked`.
- `challenge` and `rate-limited` remain declared but unproduced.
- The selector source is unchanged. The probe still uses only the reserved ChatGPT view's `executeJavaScript`; no CDP, Flow-view access, cookie/token/signed-URL/page-text logging, or dev-gate change was added.
