Implemented relative to the requested `feature/chatgpt-target-p1` base `89b32662`.
During final verification, the shared branch was moved externally to `42efc1e4`
(`feat(chatgpt): generate images on the ChatGPT target`), which contains the initial

that commit. The later completion-review fixes remain uncommitted in four source/test
files on top of `42efc1e4`; this report is also uncommitted and ignored by the existing

The product path ports the measured spike surface without CDP. It uses only
`executeJavaScript` and `sendInputEvent` for page automation, and the ChatGPT
partition session for the authenticated image download. Every page evaluation,
session probe, result wait, and image fetch used by the batch has a finite bound.

The independent completion review found and then re-verified a target-switch race:
a ChatGPT-initiated Start now snapshots both `mode` and `sessionTarget`, aborts if
either changes during preflight or tag-modal continuation, and therefore cannot
cross into the Flow engine and spend Flow quota.

## What the user now sees

With `AUTOFLOWCUT_CHATGPT_P2=1` in the existing supported macOS development launch,
the route set to `flow` + `chatgpt`, and the ChatGPT auth chip reporting ready:

1. Pressing **생성 시작** for an image scene with a text prompt and no reference
   images starts the normal image-generation progress path instead of showing
   `선택한 세션 타깃에서는 생성을 시작할 수 없습니다`.
2. The ChatGPT composer receives an explicit image instruction through the measured
   `#prompt-textarea` surface and submits through the measured
   `#composer-submit-button` surface (with the measured Enter fallback only after
   two confirmed non-submission observations).
3. Any estuary image seen before composer-clear acknowledgement is absorbed into
   D3 ownership state. A final image is accepted only when the same new estuary ID
   appears in two consecutive polls.
4. The accepted image is fetched through the persisted ChatGPT session, staged in
   the app temp directory, returned as a saved image payload, and finalized by the
   existing scene image pipeline. The user sees the generated scene image through
   the standard result UI.

If `ensureSession()` is not ready, the request is not submitted and returns a clear
login/session-ready error instead of waiting indefinitely.

## Routing and refusal boundaries

- `sourceForStage(route, 'image')` selects ChatGPT only for `flow` + `chatgpt`.
- `flow` + `flow` image requests continue through the existing Flow engine.
- API mode continues through the existing API engine.
- `sourceForStage(route, 't2v'|'i2v')` remains `api` for `flow` + `chatgpt`; no
  ChatGPT video method is used. The session-target Start UI continues to refuse
  video with a message explaining that video is routed to the API provider.
- Any image request carrying reference images is refused before submission with a
  reference-upload-not-measured reason. Manual reference upload remains refused.
- Without the existing dev flag, ChatGPT remains unselectable and its generation
  IPC admission remains disabled. API mode and `flow` + `flow` behavior are unchanged.
