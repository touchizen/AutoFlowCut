# Large Import UX Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add a free large-import confirmation, a delayed spinner that is painted before synchronous import work, and renderer-side localization enforcement for Korean notification strings.

**Architecture:** Keep import decisions in `App.handleImport`, using a pure parser-based inspection utility before any action mutates state. A reusable App-level processing hook commits and paints an overlay before invoking import work, while delaying visual disclosure for 150 ms. A test-owned lexical scanner guards only renderer notification call expressions and excludes locale catalogs and non-UI Korean content.

**Tech Stack:** React 18, Vitest, Testing Library, existing parser utilities and locale catalogs.

**Step 3: Implement the controller**

Export a 150 ms delay constant and a runner that performs this sequence:

```js
setProcessing(true)
setSpinnerVisible(false)
start the 150 ms visibility timer
await requestAnimationFrame followed by setTimeout(0)
await action()
clear timer and processing state in finally
```

The overlay is mounted whenever processing is true. Its initial CSS opacity is zero and has a compositor-friendly 150 ms delayed opacity animation; `.is-visible` exposes it immediately when the JavaScript timer commits. Only the visible state receives `role="status"`, while the mounted shell carries `data-import-processing="true"` for the pre-work commit guarantee.
