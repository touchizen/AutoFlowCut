# Native references and video in default Flow

Keep the renderer IPC and its reference plan. Share the image submission lease,
isolated composer reads, native settings/input and NetLog transport proof across
the three video modes. Before dispatch, bind each pasted image to the page's
own upload by checking project, decoded pixels, response ID and composer chip.
Check actual submit RPC, project, text, inputs and response; for videos also
check the model and capture the single returned media ID. Only this ID enters
the existing status and download path. Never retry an ambiguous paid click.
Retain the standalone legacy RPC and upscale gates.

Test the positive/negative protocol fixtures first. Then run one scene at a
time on the owned Flow test project; space submissions at least 75 seconds
apart and stop all live work immediately on a new warning. Preserve the cup.

Video rows also keep a local write-ahead record in Electron's user-data
directory. Immediately before a native click, the app atomically reserves the
local row and syncs the record to disk. After native response validation it
records the media ID. A restarted app refuses an unresolved reservation or
returns the previously confirmed ID for the same inputs. A deliberate clear or
regenerate advances the row revision; loading an older project snapshot cannot
roll the reservation back. Raw reference bytes and prompts are not stored there.

Supported reference inputs are local image files resolved by the renderer's
existing attachment/mention plan. The default video lane supports one result
per request; frame mode accepts one start image. Standalone character entities,
end frames and upscaling are outside this change. The native response collector
still requires a POSIX FIFO.
